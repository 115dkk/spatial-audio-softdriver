# 0016. 헤드폰 FIR, 빈 방향, LFE는 적재할 때 처리한다

상태: 채택, 2026-10-13. 2026-10-11에 제안했습니다(설계서 후보 8).

## 배경

구축기에서는 헤드폰 보정이 실시간 그래프의 별도 단계이고, 측정 BRIR이 없는 천장 중앙은 무음 채널로 자리만 채우며, LFE는 FC의 양이 IR을 빌려 씁니다. 세 가지가 모두 실행할 때의 그래프 문자열 안에 흩어져 있습니다.

## 결정

- `brir::prepare`가 헤드폰 FIR을 각 BRIR에 미리 접습니다. 둘 다 선형 시불변이라 결과가 같습니다.
- 레이아웃에 없는 위치는 렌더러의 VBAP가 이웃 방향에 나누므로 무음 채널이 필요 없습니다.
- LFE에 어떤 IR을 쓸지는 프로필의 정책으로 둡니다.
- 게인과 리미터의 순서(+36 dB 뒤 −1 dBFS 리미터)는 그대로 지켜야 하므로 엔진의 마지막 단계에 남깁니다.

## 정해야 할 것

M1에서 헤드폰 FIR을 접기 전과 후의 출력이 허용 오차 안에서 같은지 테스트로 확인한 뒤 채택합니다.

## 구현

- 헤드폰 FIR은 FFT 합성곱으로 각 BRIR에 접습니다. 직접 합성곱 기준과 상대 오차 1e-6 안에서 같습니다(`brir`의 시험).
- 두 귀가 모두 무음인 방향은 적재 방식(순서 WAV, 방향별 파일, 매핑 WAV, 폴더)과 무관하게 레이아웃에서 뺍니다. 뺀 방향의 이름은 준비 결과(`omitted_silent_directions`)에 남습니다. 무음 천장 트랙이 실제 방향이 되어 그쪽 소리가 사라지는 일을 막습니다.
- 모든 방향과 두 귀에 같은 앞 지연(전파 지연)은 잘라 냅니다. 각 IR의 시작점(전체 최댓값의 −60 dB를 처음 넘는 표본)의 최솟값에서 1 ms 여유를 뺀 만큼을 모든 IR에서 똑같이 자르므로, 귀 사이와 방향 사이의 시간차는 그대로입니다. 프로필 키 `trim_leading_delay`(기본 true)로 끌 수 있고, 자른 표본 수는 `trimmed_leading_frames`에 남습니다.
