# 0034. 앱에서 헤드폰(BRIR)과 스피커(룸 보정 FIR) 가운데 하나를 고르고, 헤드폰 FIR은 없앤다

상태: 채택, 2026-10-16. ADR 0016의 헤드폰 FIR 결정을 거둡니다. ADR 0030의 출력 종류를 앱에서 고를 수 있게 합니다. ADR 0013의 프로필 의도도 고칩니다.

## 배경

M4-f에서 프로필 화면에 "헤드폰 FIR" 가져오기를 두었습니다. ADR 0016이 헤드폰 FIR 하나를 모든 BRIR에 미리 접기로 정했기 때문입니다. 이 결정에는 두 가지 잘못이 있었습니다.

- **헤드폰 보정은 BRIR의 몫입니다.** 헤드폰 보정은 BRIR을 만들 때(Impulcifer) 이미 들어갑니다. 앱이 따로 받으면 두 번 보정하거나, 다른 헤드폰의 보정을 얹게 됩니다. 구축기에 있던 별도 단계를 그대로 옮겨 온 것이 원인입니다.
- **FIR이 필요한 자리는 룸 보정입니다.** SECS 2와 그 포크 SECS 2R 같은 룸 보정 도구는 실제 스피커마다 FIR을 만듭니다. 이 FIR은 스피커 출력(ADR 0030의 4단계)에 쓰는 재료이므로 BRIR과 섞일 자리가 없습니다.

그런데 스피커 출력은 지금까지 `profile.toml`로만 쓸 수 있었습니다. 앱에서 고를 수 있는 스피커는 BRIR이 없을 때 쓰는 기본 스테레오뿐이었습니다.

## 결정

- **헤드폰 FIR을 없앱니다.**
  - 지우는 자리: 계약의 `ProfileView.headphone_fir`과 `Intent::ImportHeadphoneFir`, 감독자의 가져오기와 그 오류 문장, 화면의 헤드폰 FIR 패널, `brir::Profile.headphone_fir`과 `brir::check_headphone_fir`.
  - `profile.toml`의 `[brir] headphone_fir` 키는 조용히 무시하지 않고 거절합니다. 거절 문장에는 까닭과 대안을 적습니다. 대안은 헤드폰 보정을 BRIR에 넣거나, 스피커 프로필의 `fir`로 룸 보정을 하는 것입니다.
  - 앱의 저장된 설정에 남은 `headphone_fir`는 읽을 때 버립니다.
- **출력 종류는 둘이고, 한 번에 하나만 씁니다(`ProfileKind`).** 프로필은 두 종류의 설정을 따로 가집니다. 한쪽 설정을 바꿔도 다른 쪽은 그대로 남으므로, 종류를 오가도 다시 가져올 필요가 없습니다.
  - **헤드폰:** BRIR 세트를 씁니다(지금과 같음). 가져온 BRIR이 없으면 헤드폰으로 바꿀 수 없습니다(`ImportBrirFirst`).
  - **스피커:** 아래 표의 배치 하나와, 스피커마다 선택으로 붙이는 룸 보정 FIR을 씁니다.
  - **게인:** 종류마다 따로 둡니다. 헤드폰에 맞춘 +10 dB가 스피커로 넘어가지 않게 하기 위함입니다. `SetGain`은 지금 쓰는 종류의 게인을 바꿉니다.
  - **실시간 교체:** 종류를 바꾸거나, 쓰고 있는 종류의 BRIR, 배치, FIR을 바꾸면 실시간 교체(`LiveChange::Prepared`)로 적용합니다. 채널 수가 바뀌면 출력 장치를 다시 엽니다(ADR 0030). 쓰지 않는 종류의 설정을 바꾸면 저장만 하고 엔진은 건드리지 않습니다. BRIR을 가져와도 종류는 저절로 바뀌지 않습니다.
  - **기본값:** 스피커 2.0에 FIR이 없는 상태입니다. 지금까지의 기본 스테레오(±30°, 장치의 처음 두 채널)와 같은 소리입니다.
- **앱의 스피커 배치.** Windows 채널 마스크가 있는 표준 배치 아홉 가지입니다(`ssr_types::app::SpeakerLayout`). 장치 채널 n은 마스크의 n번째 비트이고, 스피커 이름과 공칭 각도는 ADR 0029의 `Speaker` 표를 따릅니다.

  | 배치 | 마스크 | 장치 채널 순서 |
  | --- | --- | --- |
  | 2.0 | `0x3` | L R |
  | 2.1 | `0xb` | L R LFE |
  | 4.0 | `0x33` | L R Ls Rs |
  | 5.1 | `0x3f` | L R C LFE Ls Rs |
  | 7.1 | `0x63f` | L R C LFE Lrs Rrs Lss Rss |
  | 5.1.2 | `0x503f` | L R C LFE Ls Rs Tfl Tfr |
  | 5.1.4 | `0x2d03f` | L R C LFE Ls Rs Tfl Tfr Trl Trr |
  | 7.1.2 | `0x563f` | L R C LFE Lrs Rrs Lss Rss Tfl Tfr |
  | 7.1.4 | `0x2d63f` | L R C LFE Lrs Rrs Lss Rss Tfl Tfr Trl Trr |

  - **마스크와 순서:** `ssr_types::channel_layout_preset`(직접 입력과 스피커 프로필의 마스크 이름)과 같습니다.
  - **옆 쌍이 없는 배치:** 서라운드가 뒤 비트(`0x30`)에 있지만 이름은 `Ls/Rs`(110°)입니다. 7.1 뒤 쌍의 150°가 아니라 5.1 방의 공칭 각도에 두기 위함입니다. `Ls/Rs`에는 Windows 비트가 없으므로 마스크 순서 검사가 건너뜁니다.
  - **LFE:** 서브우퍼 하나입니다.
  - **저음과 정렬:** 모든 스피커가 전대역입니다. 저음 관리는 LFE를 서브우퍼로 보내는 것(+10 dB)뿐이고, 정렬(거리, 지연, 레벨)은 하지 않습니다. 룸 보정 FIR에 지연과 레벨이 들어 있으면 그대로 소리에 반영됩니다.
  - **그 밖의 설정:** 크로스오버, 거리, 레벨, 실제 각도, 표에 없는 배치는 지금처럼 `profile.toml`(ADR 0030)로 정합니다.
- **장치가 배치를 받는지 먼저 묻습니다.** 아래 세 경우에 감독자는 고른 출력 장치가 그 배치를 독점 모드로 받는지 `Host::supports_layout`으로 묻습니다. 받지 않으면 거절하고 이유를 문장으로 보입니다(`LayoutUnsupported`).
  - 스피커로 바꿀 때
  - 스피커를 쓰는 중에 배치를 바꿀 때
  - 스피커로 켤 때

  다음 경우에는 묻지 않습니다.
  - 2.0: 공유 모드 협상 경로를 쓰므로 묻지 않습니다.
  - 호스트가 답할 수 없을 때(`HostError::Unsupported`): 묻지 않은 것과 같이 그대로 진행합니다.
- **룸 보정 FIR은 스피커마다 WAV 하나입니다.**
  - 트랙이 하나면 그 트랙을 씁니다.
  - 트랙이 여럿이면 그 스피커의 장치 채널 번호와 같은 트랙을 씁니다(트랙 n = 장치 채널 n). 그 트랙이 없으면 거절합니다.
  - 이 규칙은 `profile.toml`의 `fir`에도 그대로 적용됩니다. 전에는 한 트랙만 받았으므로, 이전 파일은 뜻이 바뀌지 않습니다.
  - 길이 한도(4초)와 리샘플은 ADR 0030 그대로입니다.
  - SECS 2와 SECS 2R의 출력 형식은 공개 자료에서 확인하지 못했습니다. 그래서 룸 보정 도구들(REW, DRC, CamillaFIR 등)이 공통으로 내보내는 채널별 FIR WAV를 받는 것으로 정합니다. 형식이 다르면 그때 이 결정을 고칩니다.
  - 룸 보정 도구의 소스는 들이지 않습니다(ADR 0003, 0005). 가져오는 것은 그 도구가 만든 WAV뿐입니다.
- **FIR은 스피커 이름에 붙습니다.** 앱은 FIR을 스피커 이름(`L`, `C`, `Lss`, `Tfl`, 서브우퍼는 `LFE`)으로 기억합니다. 배치를 바꾸면 새 배치에 있는 이름의 FIR만 쓰고, 나머지는 저장해 둡니다. 그래서 7.1.4에서 5.1로 갔다가 돌아와도 FIR이 남아 있습니다.
- **`profile.toml`이 여전히 우선합니다.** 파일이 있으면 그 파일이 종류까지 정합니다. 앱의 종류, BRIR, 배치, FIR 의도는 거절합니다(`ProfileFileTakesPrecedence`). 게인은 파일 종류에 해당하는 저장 게인이 덮어씁니다.

## 계약 (ADR 0001)

- `Intent`
  - 더하는 것: `SetProfileKind(ProfileKind)`, `SetSpeakerLayout(SpeakerLayout)`, `SetRoomFir(RoomFir { speaker, path: Option })`. `path`가 `None`이면 지웁니다.
  - 그대로 두는 것: `ImportBrir(PathBuf)`
  - 없애는 것: `ImportHeadphoneFir`
- `ProfileKind`: `headphones`와 `speakers` 둘입니다. `stereo`는 스피커 2.0이 되었습니다.
- `ProfileView`
  - 쓰고 있는 종류에 대한 필드: `kind`, `name`, `gain_db`, `directions`
  - 그 밖의 필드: `from_file`, `headphones { brir }`, `speakers { layout, channels }`
  - `speakers.channels`에는 장치 채널마다 이름, 번호, 서브우퍼 여부, FIR을 담습니다.
  - 쓰지 않는 종류의 설정도 보여서, 화면이 두 종류를 나란히 보일 수 있습니다.

## 범위 밖

- **종류마다 다른 출력 장치**(헤드폰 DAC와 AV 리시버 같은 경우): 지금은 두 종류가 한 출력 장치를 같이 쓰고, 다음 결정에서 다룹니다.
- **앱에서 고치는 스피커 설정**: 거리, 레벨, 크로스오버, 각도는 앱에서 고치지 않습니다.
- **배치 목록 거르기**: 고른 장치가 받는 배치만 목록에 보이지는 않습니다. 지금은 고를 때 묻습니다.
- **헤드폰과 스피커에 동시에 내기**(ADR 0030의 범위 밖 그대로)

## 결과

- **화면:** 프로필 화면이 헤드폰과 스피커 두 탭으로 나뉩니다. 어느 탭을 보고 있는지는 화면의 보기 상태이고, 처음에는 지금 쓰는 종류를 엽니다. 각 탭에는 그 종류의 설정이 있고, 쓰지 않는 종류의 탭에는 그 종류로 바꾸는 단추가 있습니다. 화면 갤러리는 두 종류와 각 탭을 모두 찍습니다.
- **저장 설정:** 종류마다 나뉩니다. 이전 설정 파일은 이렇게 읽습니다.
  - `brir`는 헤드폰 설정이 됩니다.
  - `gain_db`는 그때 쓰던 종류(BRIR이 있으면 헤드폰)의 게인이 됩니다.
  - `headphone_fir`는 버립니다.
- **시험:**
  - 배치표와 마스크 순서
  - 이전 설정 읽기
  - 종류, 배치, FIR 의도의 실시간 교체와 거절
  - 장치 확인
  - 여러 트랙 FIR의 트랙 고르기
  - `headphone_fir` 키 거절
