# 0015. 지연을 숫자로 잰다

상태: 채택, 2026-10-13. 2026-10-11에 제안했습니다(설계서 후보 7). 측정 경로는 구현되었고, M2의 판정은 SAL PC의 측정을 기다립니다.

## 배경

구축기는 버퍼를 하나씩 줄이며 Denon 직접 재생과 귀로 비교했고, 절대 지연은 재지 않았습니다. 단계별 수치는 로그에 있지만 체인 전체의 값은 없습니다.

## 결정

드라이버 기록의 QPC(가상 DMA가 그 바이트를 지난 시각)를 `SceneBlock::source_qpc`에 실어 엔진 끝까지 보내고, 출력 장치의 재생 시각(QPC)에서 빼서 블록마다 지연을 계산합니다. 상태 화면에는 p50과 p99를(`EngineStatus::latency`), 진단 녹화에는 분포 전체를 남깁니다. 소스 앱 내부의 지연(게임에서 공간음향 인코더까지)은 이 숫자에 들어가지 않습니다.

## 정해야 할 것

M2에서 SAL 링으로 먼저 재 보고, 프리셋과 버퍼 목표를 이 숫자로 정할지 확인합니다. M2의 끝나는 조건(지연이 구축기 이하)도 이 숫자로 판정합니다.

## 구현

- 엔진은 블록마다 `source_qpc`와 출력의 재생 QPC로 지연을 재고, 상태에 p50과 p99를 냅니다(`EngineStatus::latency`). 백분위는 제어 스레드가 계산하고, 출력 스레드는 값을 고리에 쓰기만 합니다.
- 출력의 재생 시각은 단조롭습니다. 장치가 상관 읽기를 주기 전의 추정에서 측정으로 바뀔 때나 장치를 다시 시작할 때 앞 주기보다 이르게 나오지 않습니다.
- `ssr-live play --report`가 같은 숫자를 JSON으로 남기고, 시험서명 PC 안내서가 그 숫자로 판정합니다.
