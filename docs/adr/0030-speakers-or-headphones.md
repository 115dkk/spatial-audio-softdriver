# 0030. 출력은 실제 스피커와 헤드폰(BRIR) 가운데 하나이고, 둘은 믹서 뒤에서만 나뉜다

상태: 채택, 2026-10-13. ADR 0012의 교차 링 채널 수와 ADR 0020의 XTC 범위를 고칩니다.

## 배경

이 프로젝트는 AV 리시버가 하던 일을 PC 안에서 소프트웨어로 합니다. 비싼 리시버 없이, 가진 스피커와 다채널 DAC(또는 오디오 인터페이스와 앰프)로 Atmos 콘텐츠를 듣는 것이 처음 목표 가운데 하나입니다.

그런데 지금까지의 설계는 헤드폰만 다뤘습니다. 구축기가 헤드폰(개인 측정 BRIR) 기반이었고, 그 전제가 그대로 남았기 때문입니다.
- ADR 0020은 XTC를 "헤드폰 제품의 범위 밖"이라며 뺐습니다.
- CONTEXT의 '방향'은 BRIR이 측정된 위치로만 정의되었습니다.
- 실제 스피커로 내보내는 출력은 어디에도 없었습니다.

이것은 설계의 누락이었습니다.

다행히 구조는 이미 맞습니다. 믹서는 레이아웃에 맞춰 차선마다 스피커 베드로 패닝합니다(ADR 0028). 레이아웃을 BRIR 방향 대신 실제 스피커 배치로 주면, 베드가 곧 스피커에 보낼 신호입니다. 드라이버는 입력 쪽이라 바뀌지 않으므로 동결과도 무관합니다.

## 결정

- **출력 종류.** 엔진은 출력 프로필의 종류에 따라 출력단 하나를 씁니다.
  - `headphones`: 지금의 BRIR 프로필입니다. 베드를 BRIR로 합성곱해 양이 2채널을 냅니다.
  - `speakers`: 듣는 분의 실제 스피커입니다. 베드를 스피커 채널로 보냅니다.
  - 드라이버, 기록 스트림, 디코드, 장면, 공통 시간선 믹서는 두 종류가 같이 씁니다.
  - 출력 종류를 바꾸는 것은 지금 BRIR을 바꾸는 것과 같은 실시간 교체(`LiveChange::Prepared`)입니다. 장치의 채널 수가 바뀌면 출력 장치를 다시 엽니다.
- **레이아웃.** 믹서가 패닝하는 레이아웃은 출력 프로필이 정합니다.
  - 헤드폰: BRIR이 측정된 방향
  - 스피커: 프로필에 적은 스피커 위치. 공칭 각도는 ADR 0029의 `Speaker` 표가 기본이고, 실제 각도로 덮어쓸 수 있습니다.
  - 패닝은 같은 `PanGeometry`(VBAP와 spread)입니다. 위층 스피커가 없으면 높이 객체는 가상 천정을 거쳐 수평 스피커로 나뉩니다. 이것은 지금 헤드폰 레이아웃에서 하는 것과 같습니다.
- **스피커 출력의 처리**(소스 클럭 도메인, 이 순서로):
  1. **채널 배정:** 베드의 방향마다 장치 채널 하나입니다. LFE는 서브우퍼 채널로 갑니다.
  2. **저음 관리:** 스피커마다 '전대역' 또는 크로스오버 주파수(기본 80 Hz, 20~250 Hz)를 둡니다. 필터 계수와 상태는 `f64`입니다. 낮은 크로스오버와 높은 표본율에서 극점이 z = 1에 붙어 `f32`로는 응답이 틀어지기 때문입니다.
     - 크로스오버가 있는 스피커는 4차 Linkwitz-Riley 고역 통과를 받습니다. 걸러 낸 저역은 모아서 서브우퍼로 보냅니다.
     - LFE는 +10 dB(대역 내 표준 이득)로 서브우퍼에 더합니다.
     - 서브우퍼가 여럿이면 똑같이 나눕니다.
     - 서브우퍼가 없으면 저역과 LFE를 프로필이 정한 전대역 스피커로 보냅니다.
  3. **정렬:** 채널마다 레벨(dB)과 지연을 겁니다. 지연은 거리(음속 343 m/s)로 계산하거나 직접 적습니다. 가장 먼 스피커에 맞춰 가까운 스피커를 늦춥니다. 지연선은 준비할 때 잡아 둡니다.
  4. **룸 보정(선택):** 채널마다 FIR WAV 하나를 같은 분할 합성곱기로 겁니다. BRIR과 달리 채널 사이를 섞지 않습니다.
  5. **리미터:** 모든 채널을 하나로 묶은 리미터입니다. 한 채널이 넘으면 모든 채널을 같은 이득으로 줄여 음상이 흔들리지 않게 합니다. 천장 규칙은 헤드폰과 같습니다.
- **클럭 교차(ADR 0012).** 교차 링은 '양이 2채널 뒤'가 아니라 '출력단 뒤의 N채널'에 둡니다. ASRC와 트림 전략, 바닥 제어는 그대로이고, ASRC 연산은 채널 수에 비례합니다(7.1.4면 12채널).
- **출력 장치.** 기본은 WASAPI 독점입니다(ADR 0023). 채널 수와 채널 마스크는 프로필이 정합니다.
  - 표준 배치(2.0, 5.1, 7.1, 7.1.4의 위층 넷)는 `WAVEFORMATEXTENSIBLE`의 채널 마스크를 씁니다.
  - 채널 이름이 없는 인터페이스는 마스크 0(직접 출력)과 프로필의 채널 번호를 씁니다.
- **프로필.** TOML에 `kind = "speakers"`를 둡니다. `kind`가 없으면 지금의 헤드폰 프로필입니다. 적을 것:
  - `[[speaker]]`마다 이름(표의 이름 또는 임의 이름), 각도(생략하면 표), 장치 채널, 거리 또는 지연, 레벨, 크로스오버, FIR
  - `[[subwoofer]]`마다 장치 채널, 거리 또는 지연, 레벨, FIR. 저역과 LFE는 서브우퍼들에 똑같이 나눕니다.
  - 기본 크로스오버와 LFE 이득(기본 +10 dB). LFE 이득은 서브우퍼가 없을 때 저역을 받는 스피커에도 씁니다.
  - 장치 채널 수와 마스크. 마스크는 이름(`"7.1.4"`), `"direct"`, 숫자(`0x2d63f`)로 적습니다. 마스크가 있으면 Windows(그리고 HDMI 너머의 리시버)는 장치 채널 n을 마스크의 n번째 스피커로 받습니다. 그래서 표의 이름에 Windows 비트가 있는 스피커(`Lrs`, `Lss`, `Tfl` 등)는 그 순서의 채널에 있어야 하고, 마스크의 LFE 채널은 서브우퍼여야 합니다. 어긋나면 프로필을 거절합니다. `Ls/Rs`처럼 Windows 비트가 없는 이름은 검사하지 않습니다.
  - 정렬 정보(거리나 지연)가 없는 스피커와 서브우퍼는 늦추지 않습니다.
- **범위 밖(나중에 각각 ADR).**
  - XTC(스테레오 스피커의 크로스토크 제거, 2×2와 2×N): 측정한 전달 함수가 있어야 합니다. 셋째 출력 종류로 들어갈 자리는 이 결정이 만듭니다.
  - 마이크로 하는 자동 측정과 자동 룸 보정
  - 헤드폰과 스피커에 동시에 내보내기
  - ASIO 입구(ADR 0025)를 스피커 출력에 더하는 방법. 지금 ADR 0025는 2채널을 출력 단계에서 더한다고 정했으므로, 스피커 출력에서는 그 2채널을 어느 스피커로 보낼지(L/R, 또는 방향으로 패닝)를 ADR 0025를 고칠 때 정합니다.

## 결과

- README와 CONTEXT는 출력을 '실제 스피커 또는 헤드폰'으로 설명합니다. BRIR은 헤드폰 출력의 재료일 뿐입니다.
- 엔진의 출력단(`Back`)은 헤드폰과 스피커 둘로 나뉩니다. 교차 링, ASRC, 뮤트 램프, 지연 측정, 출력 싱크는 N채널을 다룹니다.
- ADR 0020의 "XTC는 헤드폰 제품의 범위 밖" 문장은 "XTC는 셋째 출력 종류로 나중에 정한다"로 바뀝니다.
- 시험:
  - 스피커 출력은 합성 프로필로 채널 배정, 저음 관리(크로스오버 합의 평탄도, LFE 이득), 정렬(지연 표본 수, 레벨), 묶은 리미터를 확인합니다.
  - 루프백 CI는 다채널 가상 케이블로 채널마다 맞는 소리가 나오는지 봅니다.

## 구현 (2026-10-13)

- **프로필(`crates/speakers`):**
  - `[[speaker]]`마다 이름, 각도(생략하면 ADR 0029의 표), 장치 채널, 거리나 지연, 레벨, 크로스오버, FIR
  - `[[subwoofer]]`마다 채널, 거리나 지연, 레벨, FIR
  - 최상위 `lfe_gain_db`(기본 +10 dB), `bass_to`(서브우퍼가 없을 때만)
  - 범위를 벗어난 값(거리 50 m, 지연 500 ms, 레벨 −60~+20 dB, FIR 4초, 장치 채널 32 초과)은 준비하기 전에 거절합니다.
  - 마스크가 있으면 Windows 채널 순서와 이름이 맞아야 하고, 마스크의 LFE 채널에는 스피커를 둘 수 없습니다.
- **출력단(`engine::chain`):** 저음 관리(LR4, `f64` 상태, 소리가 멎은 뒤 1e-30 아래는 0), 룸 FIR, 정렬 지연, 트림, 묶은 리미터 순서입니다. 룸 FIR, 지연, 트림은 채널마다의 선형 처리라 결정의 3과 4를 바꾼 이 순서도 소리가 같습니다. 리미터는 순간적으로 천장을 넘는 프레임에서도 모든 채널에 같은 이득을 겁니다.
- **런타임:** 교차 링의 표식마다 그 블록의 레이아웃(채널 수와 마스크)이 실립니다. 링은 32채널까지 담을 크기로 시작 때 잡고, 수위는 표식의 프레임 합으로 셉니다. 출력 스레드는 시작 때 설치된 프로필의 레이아웃으로 장치를 열고, 다른 레이아웃의 블록에 이르면 옛 블록을 끝까지 낸 뒤 장치를 다시 엽니다(`output_reopens`). ASRC와 출력 버퍼는 그때 새 채널 수로 다시 만듭니다.
- **장치:** `OutputOpener::open(&mut self, OutputLayout)`. WASAPI는 스테레오면 지금까지의 협상 경로를 그대로 쓰고, 다채널이면 요청한 `WAVEFORMATEXTENSIBLE`(마스크 또는 0) 그대로만 받습니다. 다른 마스크로 바꿔 받으면 소리가 다른 스피커로 가기 때문입니다. `ssr-live devices --formats`가 장치마다 공유 믹스 형식과 표준 레이아웃의 독점 지원을 보입니다.
- **시험:** 합성 프로필로 배정, 저음 관리(LR4 합의 평탄도, 극단 크로스오버), 정렬, 리미터, 레이아웃 다시 열기, 12채널 ASRC의 채널 분리, 무할당을 봅니다. CI는 VB-CABLE이 양쪽에서 받는 가장 넓은 레이아웃(8, 6, 4채널)으로 채널마다 다른 음을 보내, 각 음이 제 채널로 돌아오는지(다른 채널보다 40 dB 크게) 봅니다.
- **IR 리샘플:** 룸 FIR과 BRIR을 다른 표본율로 옮길 때 표본율 비만큼 이득을 맞춰 주파수 응답을 지킵니다. 그전에는 96 kHz로 측정한 BRIR이 6 dB 작게 들렸습니다.

## 2026-10-16 보탬 (앱에서 고르는 스피커, ADR 0034)

- **앱에서 고르기.** 앱의 프로필 화면에서 헤드폰과 스피커를 고릅니다. 앱의 스피커는 표준 배치 아홉 가지 가운데 하나입니다(`speakers::layout_profile`). 정렬, 크로스오버, 다른 배치는 지금처럼 `profile.toml`로 정합니다.
- **SECS 2R 보정.** 스피커는 SECS 2/SECS 2R이 내보낸 CamillaDSP v4 설정을 보정으로 가져올 수 있습니다. 그러면 위의 저음 관리, 정렬, 룸 FIR 대신 그 설정의 신호 사슬(`correction` 크레이트)이 처리하고, 게인과 묶은 리미터는 그 뒤에 그대로 겁니다.
