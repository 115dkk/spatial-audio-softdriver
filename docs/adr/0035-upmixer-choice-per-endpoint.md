# 0035. 업믹서는 엔드포인트마다 고르고, 먼저 VST 업믹서를 만든다

상태: 채택, 2026-10-16. ADR 0021의 크레이트 이름을 바꾸고, ADR 0020과 0021을 앱에서 고르는 방법을 정합니다.

## 배경

- **약속:** 스피커 출력(ADR 0030)에서 스테레오를 실제 다채널 스피커로 펼치는 업믹스를 약속했습니다. 업믹서는 둘입니다.
  - 퍼스트파티(ADR 0020): 원작자 저장소가 아직 공개되지 않아 시작할 수 없습니다.
  - 플러그인(ADR 0021): 사용자가 가진 VST 2, VST 3 업믹서를 별도 프로세스에서 돌립니다.
- **현재 상태:** 둘 다 설계만 있습니다.
  - 크레이트(`streamring`, `hostvst-*`, `ssr-plughost`)도 엔진의 업믹스 단계도 없습니다.
  - `features.toml`의 해당 항목은 모두 `planned`입니다.
- **사용자의 결정(2026-10-16):**
  - 업믹서는 엔드포인트마다 켜고 끕니다. 선택지는 '퍼스트파티 업믹서', 'VST 업믹서', '업믹스 안 함' 셋입니다.
  - 퍼스트파티는 나중에 기본값이 됩니다. 지금은 미구현으로 막아 둡니다.
  - 업믹스는 헤드폰과 스피커 모두에서 렌더할 수 있습니다.
  - 업믹서가 켜진 엔드포인트가 있으면, 출력 종류마다 업믹스 적용 여부를 예/아니오 스위치로 둡니다. 기본은 켜짐입니다. 업믹서를 켠 것이 곧 사용자의 뜻이기 때문입니다.

## 결정

### 무엇을 고르는가

- **엔드포인트마다 업믹서 하나.** 대상은 업믹스할 수 있는 두 엔드포인트입니다.
  - 주 엔드포인트(0, `Spatial SoftReceiver`)
  - 음악 엔드포인트(1, `Spatial SoftReceiver Music`)

  PASS 엔드포인트(2)는 비트스트림을 그대로 넘기므로 업믹스하지 않습니다(ADR 0028). (틀린 설명입니다. 끝의 "2026-10-16 고침"이 바로잡습니다. PASS는 비트스트림과 독점 PCM을 받는 입구이고, 엔진이 디코드해 렌더합니다.)
- **선택지(`UpmixerChoice`).** 다음 셋입니다.
  - `FirstParty`: 퍼스트파티 업믹서. 지금은 미구현이라 고를 수 없습니다. 화면에는 보이되 잠기고 '미구현'이 붙습니다. 감독자도 이 의도를 거절합니다.
  - `Plugin`: VST 업믹서
  - `Off`: 업믹스 안 함
- **기본값.** 저장값은 `Option<UpmixerChoice>`이고, `None`은 '기본값을 따름'입니다.
  - 지금 기본값은 `Off`입니다.
  - 퍼스트파티가 구현되면 기본값을 `FirstParty`로 바꿉니다. 그러면 사용자가 고른 적 없는 엔드포인트는 그때부터 저절로 퍼스트파티를 씁니다. 사용자가 명시로 고른 값은 그대로입니다.
  - 기본값은 감독자의 상수 하나(`DEFAULT_UPMIXER`)입니다.
- **플러그인은 엔드포인트마다 따로.** 'VST 업믹서'를 고른 엔드포인트는 자기 플러그인을 가집니다. 경로, 형식, VST 3 클래스, 저장한 상태입니다.
  - 두 엔드포인트가 모두 VST 업믹서이면 호스트 프로세스가 둘입니다. ADR 0021은 플러그인 하나에 프로세스 하나입니다.
- **출력 종류마다 적용 스위치.** 헤드폰과 스피커가 각자 '업믹스 적용'(기본 켜짐)을 가집니다(ADR 0034의 종류별 설정). 쓰고 있는 종류의 스위치가 꺼지면 모든 엔드포인트가 업믹스하지 않은 원래 스테레오를 렌더합니다.
  - 이때 플러그인 호스트는 끄지 않고, 엔진의 업믹스 단계만 대체 신호로 둡니다. 스위치를 다시 켜면 플러그인을 다시 적재하지 않고 바로 돌아옵니다.
  - 화면은 업믹서가 켜진 엔드포인트가 하나라도 있을 때만 이 스위치를 보입니다.

### 어디서, 무엇을 업믹스하는가

- **업믹스 단계의 자리.** 엔드포인트마다 디코드 뒤, 장면을 만들기 전입니다(확장 설계서 후보 10).
- **대상.** 그 엔드포인트의 소스가 2채널 PCM(L, R)일 때만입니다. (끝의 "2026-10-16 고침"이 대상을 비트스트림으로 오는 스테레오까지 넓히고, 아래 두 항목도 그 절이 바꿉니다.)
  - 다채널 PCM, 비트스트림, 객체는 그대로 지나갑니다. 형식이 바뀌면 블록 경계에서 단계를 켜고 끕니다.
  - 위치 없는 2채널(모노 합)이나 1채널은 업믹스하지 않습니다.
- **입력과 출력.**
  - 입력: 48 kHz 장면 표본율, 믹서 블록(480프레임) 단위의 스테레오
  - 출력: 플러그인이 알린 출력 버스의 스피커 배치
    - VST 3: `SpeakerArrangement`
    - VST 2: `effGetSpeakerArrangement`. 없으면 채널 수의 Windows 기본 순서(ADR 0029의 직접 배치 기본값)를 씁니다.

  각 채널은 `ssr_types::Speaker` 자리의 베드가 되고, 렌더러가 지금 쓰는 출력(BRIR 방향이나 스피커 배치)으로 패닝합니다. LFE 채널은 장면의 LFE가 됩니다. 알 수 없는 배치는 거절하고 이유를 알립니다.
- **지연 맞춤.** ADR 0021 그대로입니다. 업믹스한 엔드포인트의 장면 전체가 플러그인 지연만큼 늦어집니다(블록 하나 + 플러그인 지연 + 은폐 2 ms). 업믹스하지 않은 엔드포인트는 늦추지 않습니다. 엔드포인트마다 믹서 차선이 따로이고(ADR 0028), 시간선은 차선마다 맞춥니다.
- **대체 신호와 실패.** ADR 0021 그대로입니다.
  - 대체 신호는 같은 만큼 늦춘 원래 스테레오입니다.
  - 누락 은폐, 대체 상태, 재시작(0.5/2/8초), 10분 안에 세 번 죽으면 끄기를 따릅니다.

### 크레이트(ADR 0021 고침)

- **이름에서 VST를 뺍니다.** CLAUDE.md는 파일과 앱의 이름에 남의 상표를 쓰지 않게 합니다. 그래서 `hostvst`, `hostvst-sys`, `hostvst-proto`를 각각 `plughost`, `plughost-sys`, `plughost-proto`로 부릅니다. 앱은 이미 `ssr-plughost`입니다.
- **화면과 안내서의 VST.** 'VST 업믹서', 'VST 3 플러그인'처럼 형식을 사실로 적는 데만 쓰고, README에 상표 고지를 둡니다.
- **크레이트별 책임.** 의존 규칙은 ADR 0021, 0022와 같고, 격리 크레이트 이름만 `plughost-sys`로 바뀝니다.

  | 크레이트 | 맡는 일 |
  | --- | --- |
  | `streamring` | XT StreamRing을 저작권자(115dkk)의 허락으로 MIT로 옮긴 것 |
  | `plughost-proto` | 메시지, 상태별 시한, 실패 판단 |
  | `plughost-sys` | 격리 크레이트(Windows, VST 2 ABI, VST 3 COM, 프로세스·Job·공유 메모리·파이프·이벤트) |
  | `plughost` | 앱 쪽 `PluginProcess`와 호스트 쪽 실행 루프, `Plugin` 트레이트 |
  | `apps/ssr-plughost` | 실행 파일 |
- **unsafe 예산.** `plughost-sys`를 처음 만드는 PR에서 실제 개수로 정해 `unsafe-budget.toml`과 ADR 0022 끝에 적습니다. `ssr-policy`의 Windows 의존성과 링크 규칙 게이트도 같은 PR에서 바꿉니다.
- **엔진.** 엔진은 `streamring`과 `plughost-proto`만 압니다. 업믹스 단계는 트레이트(`Upmixer`)로 두고, 구현은 둘입니다.
  - 플러그인: 앱이 만든 공유 메모리 구역 위의 `streamring` 생산자
  - 시험용 가짜

  퍼스트파티 구현은 ADR 0020의 조건이 찰 때 같은 트레이트로 더합니다.

### 앱과 감독자

- **의도.**
  - `SetUpmixer { endpoint, choice }`. `FirstParty`는 `UpmixerUnavailable`로 거절합니다.
  - `ChoosePlugin { endpoint, path, class }`. `.vst3` 묶음이나 `.dll`입니다. 일회용 호스트로 검사해 클래스와 버스를 확인하고, 실패하면 거절합니다.
  - `OpenPluginEditor { endpoint }`. 호스트의 최상위 창으로 엽니다(ADR 0021).
  - `SetUpmixApply { kind, on }`
- **스냅샷.**
  - 엔드포인트마다 고른 값, 실제로 도는 값, 플러그인(이름, 제작사, 형식), 상태(꺼짐, 시작 중, 도는 중, 대체 신호, 실패와 그 문장), 지연, 출력 배치
  - 종류별 적용 스위치
- **저장.** 엔드포인트마다 고른 값과 플러그인, 상태 덩어리(ADR 0021의 저장 시점)를 저장합니다. 종류별 스위치도 저장합니다. 이전 설정 파일에는 이 값이 없으므로 기본값(`None`, 켜짐)이 됩니다.
- **포트.** 감독자는 플러그인 호스트를 `PluginHost` 포트로 다룹니다. Windows 어댑터는 `plughost::PluginProcess`, 시험은 가짜입니다. 업믹스 상태기계는 Linux에서 시험합니다.

### 시험

- **Linux:**
  - `streamring`: XT의 StreamRingTests를 옮긴 것
  - `plughost-proto`: 시한과 실패 판단
  - 엔진 업믹스 단계: 가짜 업믹서로 지연 맞춤, 누락 은폐, 대체 신호, 형식 전환, 무할당
  - 감독자: 의도, 기본값, 스위치, 저장 이전
- **Windows CI:**
  - 저장소 안에서 Rust로 짠 작은 시험용 업믹스 플러그인(VST 3, VST 2. 스테레오를 5.1 행렬로 펼침)을 빌드합니다.
  - `ssr-plughost`로 적재, 처리, 상태 저장과 복원을 확인합니다.
  - 일부러 죽거나 멈추는 변형으로 재시작과 대체 신호를 확인합니다.
  - 외부 플러그인을 내려받지 않습니다.

## 범위 밖

- 퍼스트파티 업믹서 자체(ADR 0020의 조건)
- 32비트 플러그인(ADR 0021)
- 플러그인 폴더 전체를 미리 검사하는 목록. 이번에는 고른 파일 하나만 검사합니다.
- 업믹스를 객체로 내는 것. 업믹스 출력은 베드입니다.

## 결과

- **화면:** 엔드포인트마다 업믹서를 고르는 곳과, 출력 종류마다 적용 스위치가 생깁니다. 퍼스트파티는 '미구현'으로 잠겨 보입니다.
- **크레이트:** `streamring`, `plughost-proto`, `plughost-sys`, `plughost`, `apps/ssr-plughost`가 생기고, `features.toml`의 해당 항목이 `implemented`가 됩니다(`upmix.first_party`는 그대로 `planned`).
- **CI:** 플러그인 호스트 잡이 생깁니다.

## 2026-10-16 고침: 세 입구 모두 업믹서를 고르고, 업믹스는 스테레오와 모노에만 한다

- **사용자의 지적:**
  - 비트스트림이라고 모두 원래 믹스 그대로만 듣고 싶은 것은 아닙니다. 지연을 감수할지는 사용자가 판단할 문제입니다.
  - 비트스트림으로 서라운드가 직접 들어오면 업믹스를 건너뛰는 것이 당연합니다.
  - 비트스트림은 비트스트림 입구(PASS)로 들어옵니다. 주·음악 입구 카드에 '비트스트림' 선택을 두면 사용자가 크게 헷갈립니다.
  - '업믹스는 모노와 스테레오에만 적용한다'는 주의 한 줄이면 충분하고, (i) 툴팁에 넣는 것이 가장 좋습니다.
- **고친 점:**
  - 위의 "무엇을 고르는가"는 PASS가 비트스트림을 바깥으로 그대로 넘긴다고 잘못 적었습니다. 그래서 PASS를 업믹스 대상에서 뺐습니다.
  - ADR 0028에서 PASS는 비트스트림(DD+, TrueHD, MAT, DTS)과 독점 PCM을 받는 입구이고, 엔진이 이것을 디코드해 다른 입구와 섞습니다.
  - 이 절은 위의 "무엇을 고르는가"와 "어디서, 무엇을 업믹스하는가"를 아래로 바꿉니다.

### 무엇을 고르는가

- **업믹서를 고르는 입구는 셋입니다.** 주(0), 음악(1), PASS(2)이고, 입구마다 업믹서 하나를 고릅니다. 선택지는 앞과 같이 퍼스트파티(미구현), VST 업믹서, 업믹스 안 함입니다.
- **입구마다 받는 소리가 다릅니다.**
  - 주와 음악은 공유 PCM을 받습니다. 주는 공간음향(MAT)도 받습니다.
  - PASS는 비트스트림과 독점 PCM을 받습니다(ADR 0028).
  - 그래서 '비트스트림 스테레오를 업믹스할지'는 PASS의 업믹서 선택이 곧 정합니다. 따로 두는 선택은 없습니다.
- **지연:** 업믹스하면 그 입구의 소리가 늦어집니다(아래 "지연"). 화면은 입구마다 이 값을 ms로 보이고, 감수할지는 사용자가 업믹서 선택으로 정합니다. 영상과 함께 오는 비트스트림을 늦추고 싶지 않다면 PASS를 '업믹스 안 함'으로 둡니다.

### 대상: 스테레오와 모노 내용

- **판단:** 디코드한 장면에서 LFE를 뺀 채널(객체)이 둘 이하이면 업믹스합니다. 실려 온 방식은 따지지 않습니다. 공유 PCM, 독점 PCM, 2.0 비트스트림을 모두 같은 규칙으로 봅니다.
- **네이티브 서라운드는 늘 그대로 냅니다.** 다채널 PCM, 5.1·7.1 비트스트림, 객체 기반 비트스트림과 공간음향이 여기 듭니다. 고르는 것이 아니라 규칙입니다.
- **판단 시점:** 비트스트림은 흐름 중간에 채널 구성이 바뀝니다(2.0 광고 뒤의 5.1 본편). 그래서 판단은 그릇 형식이 아니라 디코드한 장면의 모양으로 합니다. 모양이 바뀌면 그 입구의 차선을 다시 시작합니다. 형식이 바뀔 때와 같습니다.
- **화면 안내:** 화면은 이 규칙을 한 줄로, (i) 툴팁에 담아 보입니다. 업믹서가 도는데 지금 소리가 업믹서를 거치지 않으면, 상태 줄에 그 까닭(`UpmixBypass`)을 짧게 보입니다.

### 업믹서 입력

- **입력 배치:** 플러그인이 알린 입력 버스의 배치입니다. VST 3은 `SpeakerArrangement`, VST 2는 `effGetSpeakerArrangement`에서 읽습니다. 배치를 알 수 없는 플러그인은 거절합니다.
- **스테레오와 모노를 놓는 법:** 렌더러와 같은 `PanGeometry`로 입력 배치에 놓습니다.
  - 스테레오 입력 업믹서라면 스테레오는 1:1로, 모노는 L과 R로 갑니다.
- **LFE(2.1인 경우):** 입력에 LFE가 있으면 그리로 보냅니다. 없으면 플러그인을 거치지 않고, 같은 만큼 늦춰서 출력 LFE에 더합니다.

### 대체 신호와 업믹스하지 않을 때

- **대체 신호:** 업믹서 입력을 플러그인 지연만큼 늦춘 것입니다. 출력 모양이 늘 같으므로 믹서가 보는 객체 집합이 바뀌지 않습니다.
- **업믹스 단계가 투명해지는 경우:** 아래 가운데 하나면 장면이 지연 없이 원래대로 지나갑니다.
  - 네이티브 서라운드
  - 쓰는 출력 종류의 '업믹스 적용'이 꺼짐
  - 소스 레이트가 업믹서를 구성한 레이트와 다름
  - 업믹서가 꺼졌거나 실패함
- **위 절과 달라진 점:** "출력 종류마다 적용 스위치"는 스위치가 꺼지면 대체 신호를 낸다고 했습니다. 이 절에서는 스위치가 꺼지면 늦추지 않습니다.
- **바뀌는 순간:** 투명과 업믹스가 서로 바뀌는 순간은 그 입구의 차선 재시작입니다.
- **호스트:** 적용하지 않는 동안에도 플러그인 호스트는 켜 둡니다.
- **레이트:** 업믹서는 그 입구의 지금 소스 레이트로 구성합니다. 레이트가 바뀌면 감독자가 다시 구성하고, 그동안은 투명합니다.

### 지연

- **크기:** 업믹스 경로의 지연은 블록 둘에 플러그인 지연과 2 ms를 더한 것입니다. ADR 0021보다 블록이 하나 더 많습니다.
- **블록이 하나 더 드는 까닭:** 엔진은 장면을 들어온 크기 그대로 받습니다. 그래서 10 ms 블록으로 모으는 데 블록 하나가 더 듭니다.
- **믹서에 주는 영향:** 들어온 프레임 수만큼 내보내는 고정 지연입니다. 그래서 믹서 차선의 시간 회계는 그대로입니다.
