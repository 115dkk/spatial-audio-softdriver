# 0020. 퍼스트파티 업믹서는 Rust로 다시 써서 엔진 프로세스 안에서 돌린다

상태: 채택(조건부), 2026-10-12. 원작자 저장소의 라이선스를 확인하면 '조건부'를 지웁니다.

## 배경

유놋치의 '딸깍' 업믹서는 Python으로 짠 멀티채널 업믹서를 C++20으로 옮긴 것으로, 약 1만 줄입니다(디시 스피커 갤러리 580088, 2026-10-12). 스크린샷에는 스테레오 입력, 분리 스템 업믹스(모델 scnet_xl_ihf), 5.1 출력, 엔진 지연 8054.4 ms(그중 코어 10.7 ms)가 보입니다. 분리 모델이 수 초를 내다보고 나머지 처리는 10 ms 안팎이라고 읽었지만, 분리 모델 없이 도는 독립된 저지연 경로가 원본에 있는지는 저장소가 나와야 확인할 수 있습니다. 원작자는 BACCH 관련 코드를 뺀 별도 저장소를 내겠다고 답했고, 라이선스는 아직 모릅니다.

확장 설계서 초판은 이 C++ 라이브러리를 별도 프로세스로 붙이자고 했습니다. 그렇게 하면 unsafe FFI와 라이선스 혼합은 피하지만, 저장소에 C++ 빌드 체인이 들어오고, 업믹스 신호가 프로세스를 오가며, 1만 줄을 우리가 고칠 수 없는 채로 들고 가야 합니다.

## 결정

- 업믹서를 원작자 저장소의 파생저작물로서 Rust로 다시 씁니다. 크레이트는 `upmix`이고 루트에 `#![forbid(unsafe_code)]`를 겁니다. C++ 코드를 그대로 링크하지 않습니다.
- 시작 조건은 원작자의 저장소가 공개되고 그 라이선스가 파생저작물을 허용하는 것입니다. 라이선스가 없거나 불분명하면 ADR 0008 같은 동의를 따로 받습니다. 원작자가 구축기 작성자와 같은 사람이어도 ADR 0008의 동의가 이 업믹서까지 덮는지는 다시 묻습니다.
- `upmix`의 라이선스는 원본 조건과 양립하게 정합니다. 원본이 MIT, BSD, Apache-2.0 계열이면 우리 기여분은 MIT로 내되, 원본의 저작권 고지와 라이선스 전문, 조건과 면책 문구, Apache-2.0이면 NOTICE와 변경 고지까지 그대로 지킵니다. Rust로 다시 써도 이 의무는 없어지지 않습니다. 원본이 GPL 계열이면 사용자 모드의 MIT(ADR 0003, 잠정)를 다시 정해야 하므로, 옮기기 전에 ADR 0003과 `deny.toml`을 먼저 고칩니다.
- 원본 안에 SpatialAudioLab 소스에서 온 부분이 있으면 그 부분은 ADR 0005에 따라 읽지 않습니다. 옮긴 커밋에는 원본 저장소와 커밋 해시를 적습니다.
- 모델 가중치는 코드와 따로 봅니다. SCNet 코드(starrytong/SCNet)는 MIT이지만 scnet_xl_ihf 가중치의 출처와 사용, 배포, 변환 조건은 확인하지 못했습니다. 사용자가 직접 받게 하는 방식은 재배포만 피할 뿐 사용과 변환의 허용 여부를 풀지 않으므로, 확인하기 전에는 분리 경로를 기본값으로 켜지 않습니다.
- 엔진 프로세스 안에서 돌립니다. 근거는 우리가 고치고 시험할 수 있는 코드라는 점과, 프로세스를 넘는 블록 하나의 지연(ADR 0021)이 게임에는 비싸다는 점입니다. 외부 플러그인과 달리 손으로 쓴 unsafe가 없어 메모리를 깨뜨리지 않고, 흔한 실패(범위 밖 인덱스, `unwrap`)는 되감기 패닉이라 스레드 경계에서 잡힙니다.
- 복구 범위는 다음과 같이 정합니다.
  - 분리 작업 스레드의 패닉은 그 스레드 경계에서 잡고, 업믹스는 저지연 경로로 남으며, supervisor가 작업 스레드를 다시 띄웁니다.
  - 캡처·DSP 스레드에서 도는 저지연 경로는 `catch_unwind`로 감쌉니다. 패닉하면 그 세션 동안 업믹스 단계를 대체 신호(원래 스테레오)로 고정하고 `Snapshot`에 알리며, 캡처 스레드는 계속 링을 비웁니다. 패닉 경로에서만 일어나는 할당은 실시간 규칙의 예외로 둡니다. 워크스페이스는 `panic = "unwind"`를 유지합니다.
  - abort, 스택 넘침, 할당 실패, 무한 루프와 교착, 의존성 안의 unsafe 결함은 프로세스 안에서 복구하지 못합니다. 이것은 프로세스 안에서 돌리는 대가로 받아들이고, 엔진이 멈추면 ADR 0023의 감시가 맡습니다.
- 스레드 배치는 다음과 같습니다.
  - 분리 모델을 거치지 않는 저지연 경로(원본의 코어에 해당)는 캡처·DSP 스레드의 업믹스 단계에서 블록마다 돌고, 할당과 잠금을 하지 않습니다. 게임처럼 지연이 중요한 소리는 이 경로만 씁니다.
  - 분리 모델 추론은 작업 스레드에서 돌고 결과를 미리 잡아 둔 링으로 넘깁니다. 실시간 스레드는 링만 읽고, 추론이 늦은 블록은 저지연 경로의 출력으로 채우며 짧게 교차 페이드합니다. 저지연 경로는 늘 함께 돌므로 페이드할 두 신호가 같은 시각에 있습니다.
- 추론은 순수 Rust 추론 크레이트(tract, burn, candle 등)로 먼저 재 봅니다. C++ 추론 런타임을 엔진 프로세스에 들이면 그 런타임이 죽을 때 엔진도 함께 죽으므로 이 결정의 범위 밖이고, 필요해지면 ADR을 새로 씁니다.
- 손으로 쓰는 unsafe가 꼭 필요하면(안전한 감싸개가 없는 SIMD 내장 함수 등) `upmix-sys`로 격리합니다(ADR 0022). `upmix-sys`는 안전한 구현과 비교한 벤치 결과로 필요를 보인 PR에서만 만듭니다.
- 원본 C++ 빌드를 블랙박스로 돌린 출력을 같은 입력의 허용 오차 골든으로 둡니다. 실시간 경로에는 다른 크레이트와 같이 `assert_no_alloc` 시험을 붙입니다.
- XTC(스피커 크로스토크 제거)와 BACCH 관련 부분은 옮기지 않습니다. 업믹서의 일이 아니기 때문입니다. (2026-10-13 고침: 처음에는 "헤드폰 제품의 범위 밖"이라 적었지만, 제품은 실제 스피커로도 출력합니다(ADR 0030). XTC는 셋째 출력 종류로 나중에 따로 정합니다.)

## 결과

- 업믹스 단계의 어댑터가 퍼스트파티와 플러그인(ADR 0021) 둘이 되므로 업믹스 시임은 진짜 시임이고, 트레이트를 둡니다(확장 설계서 후보 10).
- 저장소에 C++ 빌드가 들어오지 않고, 업믹서를 Linux CI에서 시험합니다.
- 원본이 고쳐지면 우리가 따라 옮겨야 합니다. 옮긴 커밋마다 원본 해시가 있으므로 차이를 추적할 수 있습니다.
- 분리 경로의 수 초 지연은 한 엔드포인트로 들어오는 모든 소리를 늦춥니다. 그래서 분리 경로는 둘째 엔드포인트(ADR 0024)에서만 켭니다(ADR 0023).
