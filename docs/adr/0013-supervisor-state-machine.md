# 0013. 설치와 설정을 상태기계 하나로 모은다

상태: 채택, 2026-10-11 (설계서 후보 5)

## 배경

구축기의 설정은 PowerShell 스크립트, 환경 변수, mpv 인자, 관리자 창에 흩어져 있습니다. 재부팅 뒤 Denon 엔드포인트 GUID가 바뀌는 문제는 이름 조회로 풀었지만, 그 처리가 실행 스크립트마다 따로 있습니다. 앱이 시키는 대로 하면 끝나는 설치를 만들려면 이 지식이 한 곳에 있어야 합니다.

## 결정

`supervisor` 상태기계가 설치 단계, 장치 선택자, 프로필, 엔진 수명, 기본 장치 복원을 모두 쥡니다. OS에 시키는 일은 `Host` 트레이트로만 부르고, 관리자 권한이 필요한 일은 `ssr-setup` 단발 프로세스에만 둡니다. 화면은 `Intent`를 보내고 `Snapshot`을 그립니다(ADR 0001).

## 결과

- Fake Host로 마법사 전 단계, 장치 분리, 드라이버 없음, ID 변경을 Windows 없이 테스트합니다.
- 설치 모듈(`ssr-sys::install`)은 `ssr-setup`에만 링크되므로, 앱 본체가 관리자 권한 없이 돈다는 사실을 링크 단계에서 보장합니다.
- 드라이버가 얼어 있으므로 앱 업데이트는 Velopack의 사용자 권한 갱신으로 끝납니다.
- 구현은 M4입니다. M0에는 `Host` 트레이트와 `Intent`, `Snapshot`의 초안만 `ssr-types`에 둡니다.

## 2026-10-15 보탬 (M4 첫 조각)

상태기계의 핵심을 Linux에서 시험할 수 있게 먼저 만들고, Windows 어댑터는 다음 조각에서 unsafe 예산 ADR과 함께 붙입니다.

- **상태.** `Setup(단계)`, `Ready`, `Running`, `Faulted`, `Quit`입니다. 마법사 단계는 `Welcome`, `Unsupported`(OS 빌드나 아키텍처가 맞지 않음), `NotTestSigning`(시험서명 묶음인데 시험서명 모드가 꺼짐, Secure Boot 상태를 문장에 적음), `Driver`(설치 안 됨 또는 문제 코드), `RebootRequired`, `ChooseOutput`입니다. 재부팅이 필요한 상태와 시험서명 모드가 아닌 상태를 따로 두는 까닭은, 둘 다 사용자가 앱 밖에서 무언가를 한 뒤 다시 확인해야 하는 상태라 안내 문장과 다음 행동(`NextAction::Reboot`)이 다르기 때문입니다.
- **`Host` 포트.** 플랫폼 사실(빌드, 아키텍처, 시험서명, Secure Boot), 드라이버 상태, 출력 목록(우리 엔드포인트는 KS 참조로 알아보며 번호를 달아 돌려줌), 기본 장치 역할 셋의 읽기와 쓰기, `ssr-setup` 실행(UAC 한 번), 복원점 쓰기만 묻습니다. 어댑터는 Windows와 시험용 가짜 둘입니다.
- **엔진 수명.** 상태기계는 해석한 `OutputProfile`과 출력 장치를 `Launcher`에 넘겨 엔진을 띄우고 `EngineHandle`로 폴링하고, 실시간 변경을 적용하고, 멈춥니다. `supervisor::Session`이 그 구현이고, 시험은 받은 프로필과 변경을 기록하는 가짜 엔진을 씁니다.
- **출력 선택자.** 고른 출력은 식별자와 이름을 함께 저장합니다. 재부팅 뒤 식별자가 바뀌면 이름이 하나뿐일 때만 다시 찾고 저장을 고칩니다. 둘 이상이면 추측하지 않고 다시 고르게 합니다.
- **넘겨받기와 되돌리기.** 켤 때 세 역할의 이전 장치를 적은 복원점을 먼저 쓰고 역할을 바꿉니다. 끌 때는 아직 우리 장치를 가리키는 역할만 이전 장치로 되돌립니다(ADR 0023). 이전 장치가 사라졌거나 처음부터 우리 장치였으면(비정상 종료가 남긴 상태) 사용자가 고른 출력으로 되돌리고 그 사실을 적습니다. Windows에 맡겨 두면 그 역할이 우리 엔드포인트에 남아 앱이 꺼진 동안 소리가 나지 않기 때문입니다. 고른 출력도 쓸 수 없을 때만 그대로 두고 적습니다. 되돌리기 규칙은 함수 하나(`restore_roles`)이고 `ssr-guard`도 같은 함수를 씁니다.
- **복원점.** `ssr-guard`가 읽는 JSON 한 줄입니다(`version`, `ours`, `previous`의 세 역할, `fallback`(고른 출력), `app_pid`). 역할을 바꾸기 전에 쓰고 되돌린 뒤 지웁니다. 복원점이 없으면 감시 프로세스는 아무것도 하지 않습니다. 그것이 정상 종료입니다.
- **복구 가능한 결함은 기다립니다.** 엔진은 끊어진 출력이나 캡처를 스스로 다시 연결하고(250 ms부터 5 s까지 두 배씩, 한도 없음) 성공하면 `FaultCleared`를 냅니다. 감독자는 결함 알림에 엔진을 멈추거나 오류 띠를 더하지 않고 `Running`에 머물며, 화면의 상태 줄은 엔진 결함을 보고 다시 연결 중이라고 표시합니다. 15초(엔진의 가장 긴 재시도 셋) 안에 돌아오지 않으면 그때 멈추고 역할을 되돌려 `Faulted`로 갑니다. DAC를 다시 꽂는 몇 초를 기다려 주되, 사라진 장치 때문에 시스템 소리가 영영 죽지 않게 하는 것입니다.
- **`ssr-guard`의 판정.** 앱이 죽으면 되돌리고 알립니다. 출력 주기와 캡처 읽기 계수가 2초 동안 그대로면 멈춘 것으로 보아 한 번은 앱을 다시 띄우고, 또 멈추면 되돌리고 알립니다. 계수를 읽을 수 없는 것도 멈춤으로 봅니다. 이 판정은 `supervisor::guard`에 두고 시계와 관측을 넣어 시험합니다. 공유 메모리와 프로세스 감시는 Windows 조각입니다.

## 2026-10-15 보탬 (M4 프로필과 객체 지도 백엔드)

- `Settings.profile`은 BRIR 경로, 헤드폰 FIR 경로와 게인을 저장하며 `#[serde(default)]`로 옛 설정 파일을 읽습니다. 상태 폴더의 `profile.toml`이 존재하면 그 파일의 출력 종류와 배치가 우선하고, 저장한 게인만 덮어씁니다. 게인은 `Option`이라 저장한 적이 없으면(`null`이나 빠진 필드) 파일의 게인을 그대로 쓰고, 가져온 BRIR과 기본 스테레오는 0 dB입니다. 명시한 0 dB는 저장한 게인입니다. 그 파일이 없으면 가져온 BRIR로 헤드폰 프로필을 만들고, 가져온 BRIR도 없으면 기본 스테레오를 씁니다.
- 감독자는 프로필을 바꾸는 의도에서 BRIR 머리와 프로필 파일을 읽고 `ProfileView`를 갱신합니다. 제어 스레드의 1초 새로고침은 `profile.toml`의 존재 여부가 바뀌었을 때만 프로필을 다시 읽으므로, 파일을 지우면 가져오기 잠금이 풀리고 파일이 생기면 다시 걸립니다. 스냅샷 자체는 디스크를 읽거나 `brir::layout`을 다시 부르지 않습니다.
- `ImportBrir`, `ImportHeadphoneFir`, `SetGain`, `TestDirection`의 허용 위상과 오류 문장은 감독자가 정합니다. 실행 중인 게인과 시험 방향은 `EngineHandle::apply(LiveChange)`로 그대로 전달하며, 엔진의 거부(`SessionError::Rejected`)를 사용자 오류로 바꿉니다. 실행 중에 가져온 프로필은 감독자가 제어 스레드에서 준비해(실시간 스레드가 아님) `LiveChange::Prepared` 하나로 넘기고, 엔진이 받은 뒤에야 설정과 `ProfileView`, 다시 준비할 프로필을 바꿉니다. 준비나 전달이 실패하면 아무것도 바뀌지 않습니다.
- 엔진이 `NeedsPrepared`를 내면(다시 연결한 출력의 배치가 바뀌는 등) 다시 준비하는 것도 감독자의 몫입니다. `Session`은 처음 받은 프로필밖에 모르므로 `EngineHandle::poll`에서는 그 알림을 넘기기만 합니다. 감독자는 실행 중인 엔진과 함께 지금 재생하는 프로필(띄운 프로필, 그 뒤 가져온 프로필, 그 뒤 받은 게인)을 쥐고, `tick`은 알림을 기억만 하며, 셸이 `needs_prepared`를 보고 `prepare_again`을 부릅니다. 큐가 차 있으면 준비한 출력을 보관하고 `PrepareRetry`를 내며, 다음 틱에는 준비 없이 전달만 다시 시도합니다. 전달되면 준비 결과의 방향으로 캐시를 갱신합니다. 프로필이 더는 준비되지 않으면(파일이 사라짐) 출력을 다시 세울 수 없으므로 엔진을 멈추고 역할을 되돌려 `Faulted`로 갑니다. 시험 방향은 캐시한 프로필의 방향 목록으로 검사합니다. 그 목록은 엔진에 마지막으로 넘긴 프로필의 것이고, 머리만 읽은 레이아웃이 준비한 레이아웃과 같으므로(ADR 0016의 2026-10-15 고침) 엔진이 큐에 든 마지막 `Prepared`로 하는 검사와 일치합니다. 진단 녹음은 구현 조각이 올 때까지 명시적으로 거부합니다.
- 죽은 `SwitchProfile` 의도는 계약에서 없앴습니다. 프로필의 현재 값은 `Snapshot.profile`, 현재 출력 방향과 객체 지도는 `EngineStatus.directions`와 `EngineStatus.scene`이 유일한 근거입니다.

## 2026-10-16 보탬 (두 출력 종류, ADR 0034)

- `Settings.profile`은 출력 종류마다 설정을 따로 저장합니다.
  - 쓰고 있는 종류 `kind`
  - 헤드폰: BRIR 세트와 게인
  - 스피커: 배치, SECS 2R 보정 파일, 게인

  위 2026-10-15 보탬의 '헤드폰 FIR 경로'와 '기본 스테레오'는 없어졌습니다. 기본값은 FIR이 없는 스피커 2.0입니다. 이전 설정 파일은 다음과 같이 읽습니다.
  - `brir`는 헤드폰 설정이 됩니다.
  - `gain_db`는 그때 쓰던 종류(BRIR이 있으면 헤드폰)의 게인이 됩니다.
  - `headphone_fir`는 버립니다.
- 의도는 `SetProfileKind`, `ImportBrir`, `SetSpeakerLayout`, `ImportCorrection`, `ClearCorrection`입니다. `ImportHeadphoneFir`는 없앴습니다. 허용 위상은 `ImportBrir`와 같고, `profile.toml`이 있으면 다섯 다 거절합니다. 쓰고 있는 종류를 바꾸는 의도만 위의 실시간 교체 규칙(준비한 뒤 엔진이 받아야 저장)을 따릅니다. 쓰지 않는 종류의 설정은 검사한 뒤 저장만 합니다.
- 스피커로 바꾸거나 쓰고 있는 스피커의 배치나 보정을 바꾸거나 스피커로 켤 때, 감독자는 `Host::supports_layout`으로 고른 출력 장치가 그 배치를 독점 모드로 받는지 묻습니다. 그래서 `Host` 포트에 이 질문 하나가 늘었습니다.
